当前部署状态请先看 [阿里云部署状态](ALIYUN-STATUS.md)。下文为此前的 SQLite 容器部署模板，不是已部署的香港或上海 PostgreSQL/OSS 环境记录。

更新2026-10-14。Owner：Codex。提供可审阅模板，本轮未执行外部部署。当前电脑没有Docker/Caddy；已检查配置结构与服务行为，容器构建、实际HTTPS及公网运行仍须在选定环境验证。

## 运行结构

Dockerfile复制新版服务、`hc_readiness.py`与前端，用非root用户运行。应用仅在专用容器网络暴露8790，数据放持久卷`/data`；Caddy提供80/443和HTTPS。构建上下文排除本机数据、旧版、检查资料与`.env`凭据。

把compose中的`HUANCHANG_PUBLIC_ORIGIN`和Caddyfile的占位域名改为同一个已拥有的HTTPS域名。应用对外监听要求HTTPS来源、Secure登录Cookie、关闭`--demo`；未满足会拒绝启动。注册运营账户后可用`--make-admin`指定已有账号及正式数据库，无默认管理员密码。

代理仅信任专用网络的Caddy地址`172.30.88.2/32`。如果服务器现有网络与`172.30.88.0/24`冲突，须同时修改网络、Caddy固定地址和可信代理配置；不要信任整个公网或所有转发头。已用独立客户端检查可信转发后的分别计数，以及伪造转发头无法绕过限流。真实Caddy链路需部署时复核。

## 邮件

使用`deployment/.env.example`所列变量配置自有SMTP服务；保管真实`.env`，不写入仓库或验收材料。默认STARTTLS/587，也支持SSL（服务商要求时配置端口，例如465）。来源地址必须是服务商允许的发信地址；域名投递记录与收件测试需在选择服务商后确认。

未配置邮件时，界面明确提示并保留恢复码入口。配置后可验证选填邮箱、通过已验证邮箱找回。邮件任务在进程内异步投递，最多8个同时任务；验证码15分钟过期、单次使用、5次尝试上限。发信失败计数可在健康检查看到；进程中断或失败需要重新请求邮件，当前未提供持久邮件队列。

本机检查验证了验证码流程与SMTP调用的TLS/格式；没有向外部邮箱投递，不等同于真实收件成功。

## 备份、恢复与维护

按实际持久卷路径执行项目的`huanchang_backup.py`。一致性备份同时复制数据库和图片，去除登录会话与邮件验证码，设置私有文件权限。另存异地副本和备份频率需部署时确定。

恢复工具只接受尚不存在的新目标目录，先检查数据库及每张图片大小；不覆盖现有站点。例如：

```sh
python3 scripts/huanchang_restore.py --backup /private/selected-backup --target /private/huanchang-restored
```

先在新目录验证恢复，再停止正式服务、保留旧数据并切换持久数据位置。已完成本机新目录恢复、重新登录与内容/图片检查；正式主机恢复仍须演练。

`huanchang_check.py`只读检查服务响应、邮件失败计数、磁盘余量和备份时效；可传`--url`、`--data`、`--backups`。没有创建定时任务或外部告警。`/healthz`不代替真实发布、上传、评论与双账户交流检查。

## 选定环境后的验收

- 容器构建、域名/HTTPS、持久卷权限、重启与恢复；注册、上传及两个独立浏览器的交流。
- 邮件服务发信权限、域名投递配置、真实收件、验证和找回；邮件失败后的重试。
- 真实手机、常用浏览器、弱网；按受控试用人数开展并发与滥用检查。当前作品及消息历史已分批读取，创作者目录和会话摘要尚未做面向大规模数据的专项优化。
- 明确运营主体/联系方式、保留期限、删除/导出处理、举报负责人及适用的正式条款。站内已提供规则与隐私说明，不能据此宣称法律审核完成。
